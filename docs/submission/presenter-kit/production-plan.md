# Submission presenter kit — production plan

Date: 2026-09-26. About one minute, English UI, separate Japanese and English caption masters, no narration. Record actual Anvil full-population applications: two foraging agents, then four shared-market agents. Each uses 166,700 neurons. Public Sepolia is a separate seven-neuron reviewer entry point.

| Scene | What must be visible | Evidence |
| --- | --- | --- |
| Purpose | Two agents responding in the full foraging world | Real observations and state, no fabricated counters |
| Environment | Field dimensions, seed and hazard areas | Initial environment transaction and successful local receipt |
| Experience | Full-neuron foraging during collection | Confirmed stimulus inputs, actual movement and body state |
| Compare | Before/candidate scores and adopt/keep | Same environment and stimulus TXs replayed for both policies |
| Model | Full model identity and neuron count | Measured MaleCNS connectivity, engineered dynamics |
| Market | Four agents making offers and trading | Fresh Aqua and V3 settlements; confirmed outcomes update readouts |
| Receipts | One fresh receipt for each venue | ERC20 transfers and matching contract events; preserve raw receipts |
| Limits | Working comparison framework | No profitability, biological superiority or energy-saving claim |

Use dedicated local chain ports and state directories. Preserve earlier recordings, learning state and unrelated services. The recorder requires paused servers, resumes only its own run, changes target holdings through the GUI to create demand, pauses at the end and restores prior targets. It does not reset balances, learned weights or counters. No Sepolia/mainnet transactions.

Compare full-foraging policies on the exact same confirmed input TXs. A seed alone is insufficient because food coordinates also depend on TX hashes. Verify receipts and canonical block hashes before replay. Full-foraging readout selection, public Fly Lab Q-learning and shared-market online updates are distinct learning implementations.

Record a continuous raw browser video and timestamp every scene against the video's wall clock. Cut setup, navigation and long learning/settlement waits; explicitly caption omitted learning time. Keep each included segment at its original speed. Preserve raw and edited timestamps in render-metadata.json. Compact CSS and labelled excerpts of actual receipts are presentation changes; never inject result data or balances.

Validate each MP4 by full decoding, end-to-end browser playback and frames from every scene. Rebuild slides and Q&A from the new capture evidence. Verify PDF page counts, overflow, actual page renders and PPTX structure/notes; native PowerPoint rendering is a separate check.

Local raw footage, cut files and screenshots live under artifacts/submission-presenter-rerecord/. Publish only verified final MP4s, captions, documents and public-safe evidence in docs/submission/presenter-kit/.
