# Paper Trading Arena — トークンを観察し、タイミングを学ぶハエ

状態: **第2ゲームの設計案 / 売買・PnL・GUIは未実装**（2026-09-26）。[Swapイベント入力の初期実装](swap-event-game.md)と[NFT/SBT仕様草案](../standards/bio-agent-draft.md)を追加しました。既存の採餌ゲームは維持します。実資金の売買・署名・承認・送金を行わず、ハエごとの仮想資産で競います。

## 体験

トークンを花として並べ、ハエが刺激を受けて注目します。注目したトークンについて、買う・保有する・売る・見送るを判断します。保有中はトークンの近くに滞在し、売買の際に仮想残高とPnLを更新します。下位個体はその場で「？」を出し、経験から学び直します。

吹き出しの例: 「気になる」「今は待とう」「ちょっと買ってみる」「そろそろ手放す」「考えなおし中」。これはモデルの行動・状態の可視化であり、実在する感情やMaleCNS回路の活動を測定した表示ではありません。

## データの取得

Uniswap公式 [Get tokens](https://developers.uniswap.org/docs/api-reference/get_tokens) は、`sort=volume_24h` または `sort=tvl` でchainId別の上位トークンを取得できます。最初は「24時間出来高上位」を流行の操作的定義とします。SNS人気や将来性を表すものではありません。新しく急上昇したことまで示すには、順位・出来高の過去記録との比較が別途必要です。

候補を選んだら [quote API](https://developers.uniswap.org/docs/api-reference/aggregator_quote) で数量を固定した見積もりを収集します。ランキングAPIの順序だけから、返却されていない出来高数値を作りません。APIキーはサーバー側に置きます。

```text
/tokens（出来高上位の候補）
    → 候補リストと取得時刻を保存
/quote（共通の観測数量・必要な売買数量）
    → 出典付きMarketSnapshot
    → 感覚特徴 → 注目先の選択 → 売買方策
    → PaperBroker → 仮想台帳 → 純PnLランキング
                         ↓
                  経験 → 学習 → 検証
```

同じ収集プロセスから全個体に同じsnapshotを配信します。各タブで別々の時刻・入力を取る現在のGUI構成を、そのままランキングに使わない設計です。

## 反応と行動を分ける

| 層 | 役割 |
| --- | --- |
| 感覚入力 | 価格変化、変動性、観測できる流動性指標、順位変化、見積もりの古さ |
| 注目スコア | どのトークンを詳しく観察するか。利益確率とは呼ばない |
| 売買方策 | 注目先・保有状態・現金・経過時間・過去の入力から行動を選ぶ |
| PaperBroker | 残高・数量・データ鮮度・約定規則を検証し仮想台帳を更新 |

強い反応は買いの命令ではありません。高い変動性に反応した上で見送る行動も学べるようにします。急騰なら必ず買う等の方向を固定すると、タイミング学習の評価になりません。

既存 `UniswapPriceBioAgent` は価格変化を採餌環境の入力へ変換する観察モデルです。市場タイミングの学習を行っているわけではありません。新たな `PaperTradingBioAgent`、金融時系列用の観測・行動・報酬、PaperBrokerが必要です。クラスの種別と個体数は別で、同じクラスの複数個体が別の方策・経験を持ちます。

## 最初のラウンド案

以下は初期提案であり、固定要件ではありません。

- 1チェーン、共通の候補5〜10トークン、ハエ3匹。
- 各個体に同額の仮想USDC、現物の買い・保有・売り・見送り。
- 最初は1ポジションと離散的な注文サイズで行動空間を小さくする。
- 初期資産、費用、リスク制限、観測時刻を全個体で統一。
- 候補の除外だけで保有資産を消さない。売却評価を継続し、価格取得不可なら未評価扱い。
- 学習中も保有資産の時価評価を続ける。競技を離れた間の損失を免除しない。

## 仮想約定とPnL

意思決定は時刻tまでに利用可能だった観測だけを使います。仮想約定は共通の遅延後に取得できた対応数量・方向のquoteを使い、判断に利用した過去の有利な価格へ遡って約定しません。取得不能・期限切れ・経路なしは約定不可として記録します。

買いはUSDC→token、売り・清算価値の評価はtoken→USDC。一定額の小口quoteを全数量へ線形拡大して、大きなポジションの約定を仮定しない設計です。quoteは将来の実約定を保証しないため、結果には約定モデルの名前と版を付けます。

```text
純資産 = 仮想現金 + 保有数量の売却側見積価値 − 未計上の想定清算費用
純PnL = 純資産 − 初期資産
```

約定時の見積数量に含まれるLP手数料・価格影響を二重に差し引かないよう、別途控除するgas等の費用と分離します。gasのUSDC換算方法・追加slippage仮定も固定して保存します。

画面は純PnL順位を主軸とし、実現／未実現PnL、最大ドローダウン、取引回数、費用、データ鮮度を併記します。保有資産の見積もりが欠けた個体は「評価待ち」として確定順位から外し、欠測をゼロ損失として扱いません。

## 学習の成立条件

報酬の基本は費用込み純資産の増分。リスク項目を罰則に含める場合は係数を明示し、画面の純PnL順位とは分離します。売却回数や勝率だけを報酬にせず、含み損を抱え続ける方策も評価対象にします。

記録データを時系列で学習期間・モデル選別期間・未使用評価期間に分けます。各時点で実際に取得した候補リストも保存し、今日の人気銘柄を昔から知っていたことにしません。経験へ追加できるのは結果が観測済みの遷移だけです。

学習候補と元の方策は同じ未学習期間・同じ費用で比較し、さらに別の期間で評価します。固定して学習しないAgentも基準として置きます。学習後にPnLが上がった一例だけで有効性を主張しません。初期版では重み更新を検証できても利益改善は未保証です。

## GUIとチェーンの見せ方

モード表示: `PAPER / LIVE DATA`、`PAPER / REPLAY`、`PAPER / FIXTURE`。短い発表では記録済みの市場時間を速めて再生し、再生時刻・倍率を常時表示します。ライブを高速化したようには見せません。

状態表示: データ待ち、観察、買い判断、仮想約定待ち、保有、売り判断、学習、評価待ち、ラウンド終了。

取引をクリックすると観測ID・quoteの出典・意思決定時刻・仮想約定時刻・数量・費用・方策版を開きます。ペーパー注文IDをEtherscanのTxとして表示しません。

smart walletはAgentの識別情報として表示できますが、仮想残高は別のPaperAccountに保存し、オンチェーン残高と混同しません。walletの発行や資金投入は、このゲーム開始の前提にしません。

将来、チェーンへ大会ルール・モデルhash・結果記録のhashを保存する場合は、その**記録Tx**だけを実際のTxリンクとして見せます。記録の存在は利益や市場データの真正性を保証するものではありません。このアンカー機能は未実装です。

## 実装順と受入条件

1. 出典付き市場記録とfixture/replay形式を決める。同じ記録を全個体へ配信。
2. PaperBrokerと台帳を実装。費用、反対方向quote、約定遅延、資金不足、欠測をテスト。
3. 同一条件の3個体と、非学習基準Agentで同じ記録を再生。PnLを台帳から再計算可能にする。
4. 売買専用の方策・経験・学習・期間分離評価を実装。
5. 既存ゲームとは別画面で、ハエ・吹き出し・仮想取引・PnLを表示。日英対応。
6. APIキーと対象chainを設定して実データ収集を検証。実注文APIは呼ばない。

これは次に作るゲームの設計であり、現在のGUIや既存の価格観察テストがペーパートレードを検証している意味ではありません。
