# Display language (i18n)

The header offers System (default), English, and Japanese. System resolves to Japanese when `navigator.language` is `ja` or `ja-*`, and English otherwise. It uses the browser's exposed language, which may differ from the OS.

The selected preference (`system`, `en`, or `ja`), rather than the resolved language, is stored at `fly-lab.language` in localStorage. This lets System follow later browser changes. If storage is unavailable, switching works for the current tab only.

## Scope and data boundaries

UI text, controls, accessibility labels, connection/transaction status, receipts, learning results, events, and Canvas bubbles are translated. Technical identifiers and proper names are preserved where appropriate.

Switching language does not reset the run, selection, unsent input, or pending transaction. It never changes TX hashes, registry addresses, event names, model/agent IDs, revisions, or JSON export formats. History translation affects display only, not stored events.

## Implementation

- `apps/frontend/i18n.js`: language resolution, persistence, translation, and DOM updates.
- `apps/frontend/messages.js`: source strings, translations, and parameterized templates.
- `apps/frontend/app.js`: `translateDOM()` at rendering boundaries and `translate()` for Canvas bubbles.

DOM translation retains original text and attributes in a WeakMap; it does not reverse-translate rendered text or recreate inputs/event handlers. Unknown strings fall back to the original, including unrecognized RPC errors.

Add new copy to the dictionary. Use placeholders such as `{name}` for dynamic sentences; never replace internal event/model values with translated strings. Use `data-no-i18n` for technical text or language names that must remain unchanged.

## Verification

```sh
# Dictionary and language resolution; no server required
node --test tests/i18n.test.mjs
# Browser verification after starting Anvil + Workers
npm run test:i18n
```

The browser check submits one stimulus to local Anvil. Do not run alongside `test:local` or recording.

Coverage includes system defaults, unsupported-language fallback, explicit selection, state preservation, reload persistence, open receipts, learning status, untranslated Japanese in English mode, and mobile overflow. Outputs: `artifacts/i18n/`.

Japanese browser tests and captioned recordings explicitly use `locale: ja-JP`; this does not change the product's System default.

## Documentation convention

Unqualified documentation filenames and directory READMEs use English. Japanese editions use `.ja.md` or `-ja.md`; intentionally bilingual material uses `ja-en` or an explicit bilingual designation. Generated default documentation must select English content and images.
